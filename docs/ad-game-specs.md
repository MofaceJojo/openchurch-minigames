# 虚假广告玩法复刻 · 开发规格书

**给 Hermes 的交付文档**。目标:复刻手游广告里**看起来很好玩的那个版本**,不是原版游戏。
广告之所以吸引人,是因为它把一个**一眼看懂、五秒见效、有明确因果**的小机制单独拎出来演了一遍——
原版把它埋在体力条和内购里所以很烂,但那个机制本身是好的。我们只要那个机制。

> **说明**:本文档依据"虚假手游广告"这一类型中反复出现的经典桥段编写,
> 未能核对具体视频内容。如有遗漏的玩法,补充描述后再增补章节。

---

## 一、通用工程约定(所有游戏必须遵守)

沿用本仓库已有两个游戏(`shepherd-snake`、`peekaboo-town`)的结构,不要另起一套。

### 文件结构

```
<game-slug>/
├── core.js     ← 平台无关逻辑:状态、规则、关卡曲线、命中判定。禁止出现 DOM / canvas
├── render.js   ← 只读 state 绘制,不改逻辑
├── audio.js    ← 纯 WebAudio 合成音效,不引入任何音频文件
└── index.html  ← 外壳:画布自适应、输入、存档、音效开关
```

- 三个 js 都用 `var Xxx = (function(){ ... })()` 包裹,末尾 `if (typeof module !== "undefined") module.exports = Xxx;`
  ——这样能直接用 node 跑逻辑回归测试。
- **零依赖、零构建**,`index.html` 双击即可运行。
- 脚本引用带 `?v=N`,改动后手动 +1,避免浏览器缓存旧版。

### 画布与坐标

- 虚拟像素画布(竖屏),推荐 `240 × 360` + HUD 26,像素风但足够细腻。
- 内部按 `SS = 2` 超采样绘制,再用 CSS 缩放铺满屏幕;`image-rendering: pixelated`。
  **不要用整数倍缩放限制画布尺寸**,否则手机上会缩成一小块。
- 屏幕坐标 → 虚拟坐标必须按 `getBoundingClientRect().width` 换算,不能用缩放系数:

```js
function toVirtual(e) {
  const r = cv.getBoundingClientRect();
  const k = Core.W / r.width;
  return { x: (e.clientX - r.left) * k, y: (e.clientY - r.top) * k - Render.HUD };
}
```

### 设计红线(违反即返工)

0. **UI 一律纯英文**。开发文档可中文,玩家看到的每个字必须是英文。
1. **可读性第一**:大元素、高对比。提交前自己截图看一眼,看不清就重做。
2. **画面必须明朗**:蓝天、暖色、笑脸。不做阴暗压抑的画面。受众是孩子和女性玩家。
3. **动作和音效必须搞笑**:被消灭的东西要打着旋儿飞出去,失败要有放屁号,不要严肃的打击感。
4. **娱乐性 >> 难度**:前 80% 的关卡应当零压力,难度只在最后一小段抬头。
5. **三档难度** `Gentle / Normal / Brave`,菜单页可选,存 localStorage。Gentle 要真的轻松。

### 音效基线(照抄 `peekaboo-town/audio.js` 的写法)

| 事件 | 声音 |
| --- | --- |
| 成功 | 滑哨升空 + "啵" |
| 失败 | 放屁号下滑 "呜哇——" |
| 过关 | 滑稽小号凯旋 |
| 失败结算 | 经典 wah-wah-waaah 下滑长号 |
| 界面点击 | 短促方波 |

`AudioContext` 必须在**首次用户手势**里 `init()`,否则浏览器不给发声。右上角放静音开关,状态存本地。

### ⚠️ 交付前必须跑的自检(硬性要求)

> 这一节是血的教训。`holy-bubbles` 交付时看起来完全正常,实际上**丢下第一颗泡的瞬间游戏就卡死**——
> 因为 `render.js` 里用了两个未定义的变量。代码从没被真正运行过。
>
> **只在浏览器里点开看一眼首屏,是查不出这类问题的**:首屏没有炸弹、没有爆炸、没有死亡动画,
> 崩溃代码根本不会被执行到。而 canvas 绘制抛异常会中断 `requestAnimationFrame` 链,
> 整个游戏静止,画面还停在最后一帧——看起来像"卡住了",不像"报错了"。

**每个游戏交付时必须附带一个 `selftest.js`,并贴出运行结果。** 模板:

```js
/* node selftest.js —— 不需要浏览器,用打桩 canvas 把每个状态都画一遍 */
global.window = {};
const Core = require("./core.js");
const src = require("fs").readFileSync("./render.js", "utf8");
const Render = eval(src + "; Render");

// 打桩 canvas:任何方法都存在且不报错,只为跑通绘制路径
const ctx = new Proxy({}, {
  get(t, k) {
    if (k === "createRadialGradient" || k === "createLinearGradient")
      return () => ({ addColorStop() {} });
    if (k === "measureText") return () => ({ width: 10 });
    if (typeof k === "string") return () => {};
    return t[k];
  },
  set() { return true; }
});

let bad = 0;
function shot(label, st) {
  try { Render.draw(ctx, Core, st, 30, 1.0); }
  catch (e) { bad++; console.log("✗ " + label + " → " + e.constructor.name + ": " + e.message); }
}
```

必须覆盖到的状态,**一个都不能少**:

| 必测状态 | 为什么 |
| --- | --- |
| 菜单 / 关卡开场 / 游戏中 / 过关 / 失败 | 每个 overlay 都有独立的绘制分支 |
| **场上有可交互物时**(炸弹、道具、子弹、拖动中的线) | 首屏没有,最容易漏 |
| **特效播放中**(爆炸、死亡、庆祝)的 0% / 50% / 100% 三帧 | 动画分支常引用未传入的参数 |
| 三档难度 × 首关 / 中间关 / 末关 | 难度参数常常根本没接上 |
| 全部关卡的生成结果 | 目标是否出界、数量是否足额 |

再加四条逻辑断言:

1. 每一关的**所有目标都完整落在画面内**(出界 = 那关永远过不了)
2. 模拟点击目标中心 → 必须命中
3. 成功 / 失败 / 超时 三条路径各触发一次,`mode` 流转正确
4. **三档难度必须产出不同的数值**——把 `gentle` 和 `brave` 的关卡参数打印出来对比,
   相同就是没接上(`holy-bubbles` 就是这样:`newRoom` 把已解析的难度对象又传给
   `roomPlan` 再解析一次,结果三档全部退化成 Normal)

### 验收标准(每个游戏都要有)

用 node 写一段回归脚本,至少覆盖:

1. 全关卡 × 全难度:关卡可生成、目标数量足额、**所有可交互物完整落在画面内**
   (这是最容易翻车的地方——生成到屏幕外的目标会让那一关永远过不了)
2. 成功 / 失败 / 过关 / 超时 四条路径各触发一次
3. 命中判定:模拟点击目标中心必须命中
4. 渲染打桩:所有模式 × 动画关键帧跑一遍,零异常

## 二、玩法规格

以下每个玩法都给出:**广告里的样子 → 核心循环 → 信仰主题换皮 → 关键实现点 → 难度曲线**。

---

### 1. Pull the Pin(拔销子救人)

> 广告里出场率最高的一个。

**广告里的样子**:一个小人被困在下方,上面有几根横插的销子挡着岩浆/沙子/怪物。
你按顺序拔销子,让水流冲走怪物、或让岩浆流到别处,把人救出来。拔错顺序人就没了。

**核心循环**:观察 → 推演顺序 → 依次点击 → 看物理演出 → 成功/失败。
**乐趣来源**:因果链一眼看懂,但顺序要想一下;演出夸张。

**信仰换皮**:**Living Water 活水**
被困的是一个人,上面有几道闸。拔对闸,活水冲下来把挡路的荆棘/枯枝冲走,人得着水站起来欢呼。
拔错则水流走空了,配放屁号。

**关键实现点**:
- **不要接物理引擎**。用格子化的"液体流动"即可:液体是一堆 2×2 的粒子,每帧尝试向下 → 左下 → 右下移动,
  被挡就堆积。几十行代码,效果足够。
- 销子 = 一条水平矩形,点击后向外滑出并消失,`solid` 数组对应格子清空。
- 每关是一份手写的关卡数据(不要程序生成),字段:`pins[]`、`walls[]`、`liquidSpawn`、`person`、`hazards[]`。
- 判定:液体粒子接触 `person` 且未接触 `hazard` → 过关。
- 关卡数据放 `core.js` 顶部的数组里,方便调。

**难度曲线**:1-6 关只有 2 根销子且唯一解;7-15 关 3 根销子 + 一个诱饵;16+ 关加"必须先放掉一部分水"的两段式。

---

### 2. Save the Person(画线救人)

**广告里的样子**:小人正掉向尖刺/水池,你用手指画一条线当作平台/桥,把他挡住或引导到安全处。

**核心循环**:看清落点 → 画一笔 → 看物理演出。
**乐趣来源**:一笔定生死,画得越巧越爽。

**信仰换皮**:**The Bridge 桥**
一个人正往深谷坠落,你画一道光的桥托住他,把他引到对岸的教堂门口。
墨水有限(一条进度条),画多了不够用。

**关键实现点**:
- 画线 = 记录 `pointermove` 的点序列,存为若干线段;每段成为一个**静态碰撞体**。
- 小人是一个圆,做最简单的圆-线段碰撞 + 反弹(不需要完整物理引擎,`vy += g`,碰到线段就沿法线反射并衰减)。
- 墨水 = 线段总长度上限,画的时候实时扣,用完停笔。
- 失败:碰到尖刺 / 掉出画面。成功:落进终点区域。

**难度曲线**:先给宽大的终点区,后期终点变窄、加移动障碍、墨水变少。

---

### 3. Braid / Untangle(解绳结)

**广告里的样子**:几条绳子/铁链交叉缠成一团,拖动端点让它们不再相交,解开后困着的人掉下来获救。

**核心循环**:找到交叉 → 拖动端点 → 交叉数归零。
**乐趣来源**:纯视觉解谜,零阅读门槛,解开瞬间很解压。

**信仰换皮**:**Loosen the Chains 松开锁链**
几个人被交叉的锁链拴在一起,你拖动锚点解开所有交叉,锁链断开,人一个个跳起来。

**关键实现点**:
- 经典的"平面图去交叉"题。节点 = 可拖动的点,边 = 线段。
- 每帧计算所有边两两是否相交(线段相交判定,`O(n²)` 完全够用,边不会超过 20 条)。
- 相交的边画成红色高亮,不相交画正常色 —— 这是最重要的反馈。
- 交叉数为 0 立刻过关。
- **关卡生成法**:先随机放好一组不相交的点位(保证有解),再把这些点打乱位置作为初始状态。
  绝不能随机连边——那样可能无解。

**难度曲线**:4 节点 5 边 → 逐步加到 10 节点 18 边。

---

### 4. Choose the Right Gate(选门 / 倍增闸)

**广告里的样子**:一队小人向前跑,前方两道门写着 `×3` 和 `+5`、或 `刀` 和 `盾`,选对了队伍暴涨,选错了减员。最后撞 Boss。

**核心循环**:算一下哪个更划算 → 左右移动选门 → 看队伍变化 → 终点结算。
**乐趣来源**:数字暴涨的爽感 + 每次都在做一个很小的心算。

**信仰换皮**:**Gather the Flock 聚拢羊群**
你带着一队信徒往教堂走,一道道门上写 `×2` `+8` `−4`,选对了队伍越来越长,
终点是一扇教堂大门,人数够就推开门,不够就被挡在外面(门"砰"一声,放屁号)。

**关键实现点**:
- 是**自动前进的跑酷**,玩家只控制左右。世界向下滚动即可,不必真的移动角色。
- 队伍用"人数 → 画多少个小人"的方式表现,超过 20 个就画成密集小点,避免性能问题。
- 门 = 一对矩形,带 `op`(`mul`/`add`/`sub`)和 `value`;角色所在 x 落在哪一半就应用哪个。
- 终点 Boss/大门:`需要人数`,达标则播放推门 + 欢呼,否则失败。

**难度曲线**:先给明显的优劣(×3 vs +2),后期给需要真算一下的(×2 vs +15,当前 12 人)。

---

### 5. Water Sort(分色倒水)

**广告里的样子**:几个试管里混着多种颜色的液体,倒来倒去直到每管一色。

**核心循环**:点起点管 → 点目标管 → 倒 → 直到全分好。
**乐趣来源**:纯逻辑、无时间压力、完成时非常舒服。是最适合"放松身心"的一种。

**信仰换皮**:**Stained Glass 彩窗**
不是试管,是几列彩色玻璃碎片,分好色后拼成一扇教堂彩窗,阳光透进来。

**关键实现点**:
- 规则:只能把顶部**连续同色**的一段倒进"空管"或"顶部同色且有空位"的管子。
- **必须保证可解**:从已解好的终局状态开始,反向随机执行合法的"倒回"操作若干步来生成关卡。
  正向随机填色会产出无解局。
- 加一个"撤销"按钮(这类玩法没有撤销会很烦躁)。
- 无时间限制、无失败;卡住可重开本关。

**难度曲线**:3 色 4 管 → 8 色 10 管;空管数从 2 减到 1。

---

### 6. Parking Jam(挪车脱困)

**广告里的样子**:停车场塞满车,点一辆车它就沿车头方向直线开走,被挡住就开不动。要按顺序清空。

**核心循环**:看清谁挡谁 → 点顺序 → 全部开走。
**乐趣来源**:一眼看懂,解开时连锁通畅。

**信仰换皮**:**Make Way 让路**
街上挤满了推车、驴车、摊位,挡住了通往教堂的路。按顺序让它们离开,最后一位坐轮椅的老人得以通过。

**关键实现点**:
- 网格化:每辆车占 1×2 或 1×3 格,带朝向。点击 = 沿朝向逐格检测,全空则驶出画面,否则原地抖一下 + 放屁号。
- 关卡数据手写,字段 `{x, y, len, dir}`。
- 抖动反馈很重要——玩家要立刻知道"是被挡住了",而不是"我点错了"。

**难度曲线**:5 辆 → 14 辆;后期加"只能横向/纵向"的固定障碍。

---

### 7. Pin Rescue(热气球 / 升降救援)

**广告里的样子**:一个人挂在高处/坠落中,你点击控制升降或抛物,把他接住。

**信仰换皮**:**Catch the Fallen 接住坠落的人**
你在下面举着一块布(像消防救生毯),左右移动接住从楼上掉下来的人,接住的人排队站到旁边挥手。
漏掉一个,画面上的教堂窗户暗一格。

**关键实现点**:
- 最简单的一个,适合先做:掉落物 + 左右移动的接盘 + 碰撞检测。
- 接住的人做一个夸张的弹跳动画,然后跑到边上排队。
- 掉落速度和频率随关卡上升;Gentle 档接盘更宽。

---

### 8. Hair Salon / Glow-up(变干净变漂亮)

**广告里的样子**:一个脏兮兮的角色,你刷牙、洗头、剪指甲,一步步变干净漂亮,最后闪光定妆。

**核心循环**:选工具 → 在角色身上涂抹 → 进度条走满 → 下一步 → 最终定妆。
**乐趣来源**:即时反馈 + 前后对比,零失败压力。**女性和儿童受众里最受欢迎的一类**。

**信仰换皮**:**Wash and Be Clean 洗净**
(参考乃缦在约旦河洗净的故事)一个满身尘土的旅人来到井边,
你用水冲、用布擦、递上干净衣裳,最后他抬起头,画面亮起来。
**避免任何"丑=坏"的暗示**,文案要写成"风尘仆仆",不是"脏"。

**关键实现点**:
- 用**遮罩擦除**实现:上层画"脏"的图层,玩家拖动时在遮罩上画圆并擦掉,露出下层干净的图。
  `ctx.globalCompositeOperation = "destination-out"` 就够。
- 进度 = 遮罩剩余不透明像素比例,可以每隔几帧采样一次 `getImageData` 估算,不必每帧算。
- **完全没有失败**,只有进度。这是它受欢迎的原因,不要加时间限制。

**难度曲线**:不做难度,做**步骤数**递增(2 步 → 5 步)和更精细的部位。

## 三、建议的开发顺序

按"实现成本 / 效果"排序,建议 Hermes 从上往下做:

| 顺序 | 玩法 | 理由 |
| --- | --- | --- |
| 1 | Catch the Fallen(接住坠落的人) | 最简单,一天能出可玩版,用来跑通工程约定 |
| 2 | Water Sort(彩窗分色) | 无时间压力、最适合"放松身心"的定位;纯逻辑无物理 |
| 3 | Untangle(松开锁链) | 零阅读门槛、解压感强;算法简单 |
| 4 | Parking Jam(让路) | 网格逻辑,无物理 |
| 5 | Gather the Flock(聚拢羊群) | 数字暴涨爽感强,但要调平衡 |
| 6 | Pull the Pin(活水) | 需要写粒子液体,成本上一个台阶 |
| 7 | The Bridge(画桥) | 需要碰撞反弹,最容易做得手感差 |
| 8 | Wash and Be Clean(洗净) | 需要遮罩擦除 + 美术资源最多 |

**每做完一个,先截图给用户看画面,确认"明朗、搞笑、看得清"三条,再往下做。**
（历史教训:夜景版《Night Watch》因为画面阴暗被整个推翻重做过一次。）

## 四、关卡密度基线(别把地图填满)

`holy-bubbles` 的另一个问题不是 bug,是手感:棋盘 11×11 共 121 格,固定墙 56 个、木箱 41 个,
**可走区域只剩 24 格,占 20%**。经典炸弹人的可走区通常是 60–70%。结果就是开局被箱子焊死,
大部分时间在拆箱子而不是在玩,自然不好玩。

通用基线:

| 类型 | 建议 |
| --- | --- |
| 网格类(炸弹人 / 挪车 / 推箱) | **可走区 ≥ 55%**;障碍宁少勿多 |
| 找隐藏物 | 目标之间间距 ≥ 2 个目标宽度,避免叠在一起 |
| 跑酷 / 选门 | 玩家每个决策点之间至少留 1.2 秒反应时间 |
| 解谜(倒水 / 解结) | 初始状态必须**从已解状态反推生成**,保证有解 |

先按基线做,再根据试玩收紧——**不要一上来就往难里调**。
